# Лабораторная работа 2. Пользовательский блочный кеш

В работе требуется реализовать блочный кеш страниц, функционирующий в пространстве
пользователя. Кеш необходимо оформить как динамическую библиотеку `vtpc`, которая
предоставляет минималистичный API, аналогичный системным вызовам для работы с
файлами:

- `int vtpc_open(const char *path);`
- `int vtpc_close(int fd);`
- `ssize_t vtpc_read(int fd, void *buf, size_t count);`
- `ssize_t vtpc_write(int fd, const void *buf, size_t count);`
- `off_t vtpc_lseek(int fd, off_t offset, int whence);`
- `int vtpc_fsync(int fd);`

Именно эта библиотека является точкой входа для тестов. В текущем репозитории
реализована заглушка, полностью проксирующая вызовы в ОС. Её необходимо заменить
на полноценный кеш.

## Нагрузчик `ema_replace`

Для проверки производительности предоставлен нагрузчик `ema_replace`, который
ищет в файле подстроку и заменяет её на строку такой же длины. Он доступен в
двух вариантах:

- `loader_ema_replace_orig` — работает напрямую с системными вызовами.
- `loader_ema_replace_vtpc` — использует API кеша `vtpc` и предназначен для
  сравнения производительности после внедрения собственного кеша.

Оба варианта принимают одинаковые параметры:

```
--file <path>
--needle <string>
--replacement <string>
--repeat <count>
[--buffer-size <bytes>]
[--generate-size <bytes>]
[--seed <number>]
[--fsync]
```

Опция `--generate-size` позволяет создать или перезаписать файл случайными
данными перед выполнением замены. В отчёте по лабораторной работе необходимо
привести результаты измерений для обоих вариантов нагрузчика.

## Сборка

```
cmake -S . -B build
cmake --build build
```

В директории `build/loaders` будут доступны оба вариантов нагрузчика, а в
`build/vtpc` — собранная динамическая библиотека с кешем.

## Блоковый кеш `vtpc`

Библиотека `vtpc` реализует страницу кеша фиксированного размера с политикой
LRU. Кеш работает поверх блочного интерфейса файла и перехватывает операции
`read/write/lseek`. Все данные читаются и записываются блоками, а при вытеснении
грязные блоки синхронизируются с диском. Размер блока и количество блоков
настраиваются через переменные окружения:

- `VTPC_BLOCK_SIZE` — размер блока в байтах (по умолчанию 4096);
- `VTPC_CACHE_BLOCKS` — количество блоков в кеше (по умолчанию 128).

Таким образом можно измерить влияние собственного page cache: сначала запустить
`loader_ema_replace_orig`, затем `loader_ema_replace_vtpc` на одинаковых данных
и сравнить время.
